# Memento 产品叙事统一口径

> 状态：产品主页、PRD、路线图、设计系统与对外说明的共同文案基线
> 更新日期：2026-08-23
> 适用范围：所有解释 Memento 是什么、解决什么问题、如何工作以及如何接入外部 AI 的文档

## 1. 一句话定义

Memento 是一位运行在电脑里的自动笔记与认知秘书。它接住散落在不同窗口和关系里的意图，沿时间整理成对你的长期理解，再把相关记忆带回真实工作。

## 2. 三项核心价值

### 01 · 接住正在发生的意图

**功能标签：无摩擦的多场景记录**

在聊天、网页、文档、AI、截图和语音现场主动触发记录。原文、时间、来源和原始资产先保存在本地，不要求离开当前窗口重新复述。

### 02 · 长期理解你的形状

**功能标签：可追溯、可修订的长期理解**

Agent 逐条整理记录，跨时间连接反复出现的关系，形成认知地形与少量当前理解。每项理解都能回到证据、边界、反例和变化原因，也允许用户修订或撤回。

### 03 · 让每个 AI，都从同一个你开始

**功能标签：可调用的个人记忆**

通过 Memory、MCP 和本地工具，把与当前任务相关的理解带入写作、研究、编程与其他 AI。数据保存在本地，调用范围由用户决定，无需在每个窗口重新解释自己。

## 3. 从记录到工作的完整路径

```text
接住意图
→ 保存本地事实
→ 逐条整理为可读记忆
→ 跨时间形成主题与认知地形
→ 多个主题收束为当前理解
→ 按任务调用相关个人记忆
→ 将工作中的新证据带回 Memento
```

这条链路由三个认知层和两个端点组成：记录入口接住现场；主题地图呈现长期关系；形成依据保留证据链；“她理解的我”给出少量当前判断；个人记忆接口把相关理解带回工作。

## 4. 文案层级

| 层级 | 回答的问题 | 统一表达 |
| --- | --- | --- |
| 用户价值 | 用户最终得到什么 | 让每个 AI，都从同一个你开始 |
| 产品能力 | Memento 提供什么 | 可调用的个人记忆 |
| 工作方式 | 如何进入真实任务 | 通过 Memory、MCP 和本地工具按任务读取相关理解 |
| 信任边界 | 谁决定数据怎样使用 | 数据保存在本地，调用范围由用户决定，每次读取与写回可追溯 |
| 技术对象 | 系统怎样实现 | `MEMORY.md`、Context Pack、ContextGrant、MCP、Local Tool、Read Audit |

面向用户的标题优先表达结果。`MCP`、`授权调用`、`多端接入`、`ContextGrant` 和审计协议进入功能说明或技术文档，不承担核心价值标题。

## 5. 标准用语

优先使用：

- 接住正在发生的意图
- 长期理解你的形状
- 让每个 AI，都从同一个你开始
- 可调用的个人记忆
- 把对你的理解重新接入真实工作流
- 数据保存在本地，调用范围由你决定
- 每项理解都能回到证据，也能被修订或撤回

停止作为核心标题使用：

- 让理解被授权调用
- 支持多端接入
- 跨 AI Context
- 个人上下文接口
- 可授权调用的个人 Context 来源

这些词可以在机制说明中出现，但必须先说明用户得到的结果。

## 6. 当前能力与目标能力

### 当前可陈述

- 多种入口将原始记录、时间、来源与资产保存在本地
- Agent 对单条记录进行整理，并保留原文与变化理由
- 跨时间关系可以形成主题、认知地形和少量长期理解
- 用户能够查看来源、修订、删除或停止使用相关理解
- 后端已经具备个人记忆读取、范围控制与审计的离线对象合同

### 仍需按目标能力表达

- 将完整个人记忆稳定接入不同外部 AI 的产品化体验
- 面向真实任务的自动检索、范围确认和工作结果回流
- `MEMORY.md`、MCP 与本地工具的正式发行、安装和端到端用户验收

对外页面需要明确区分 CURRENT 与 NEXT，避免把合同、固定演示或离线验证写成已经正式交付的用户能力。

## 7. 各文档的叙事职责

- 产品主页：先用静态电影封面建立“记忆是诠释”的主题并给出产品愿望，随后直接呈现三项价值和真实 Demo，再展开记录、地形、理解与调用的故事
- PRD：引用三项统一价值，并明确本 PRD 负责哪一段链路
- 产品终态：说明三层认知如何最终形成可调用的个人记忆
- 路线图：围绕三项价值安排验证顺序，不把技术接口当作独立价值
- 后端设计：使用 ContextGrant、MCP 和审计等准确术语，同时在章节开头标明其承接的用户价值
- 设计系统：页面标题使用价值语言，机制词进入副标题、注释和交互说明
