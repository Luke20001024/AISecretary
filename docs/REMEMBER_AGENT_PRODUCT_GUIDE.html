Agentic Workflow 兼容入口 · 产品说明书

Agent 做判断，
Workflow 控流程。

在独立 Agent V1 兼容入口中，你可以点击“现在整理”发起一次近期理解核对。Agent 找出与你本人有关、值得长期保留的理解并做最终判断； Workflow 负责查证、限制工具和预算；本地校验通过后，结果才会进入“她眼中的我”。

v0.9.0 入口边界：本页的“现在整理 / 检查最近 14 天”是独立 Agent V1 兼容入口。当前认知主页以“原文保存 → 逐条整理 → 归并今天 / 21:00 日流程 → 必要时长期判断”为主流程。

01 · 30 秒看懂

这个产品究竟交付什么？

它把分散在日常记录里的长期信号，整理成少量可核验、可继续修改的“关于你的理解”。 它交付长期理解与证据链，不交付一段聊天回复。

01 立即整理或固定每日运行

打开“关于我”，点击“现在整理”，或开启每日 21:00 计划。仅查看页面和依据不会调用 DeepSeek。

02 Agent 负责关键判断

判断有没有候选、关联哪条旧理解、是否需要查历史，以及最终应该更新还是停止。

03 程序把写入风险关住

只有真实来源、逐字引用、版本和用户删改都通过校验，才会生成一版新的长期理解。

02 · 运行流程

一次整理，经过六个环节。

红色节点由 Agent 做语义判断，蓝色节点由 Workflow 执行受控调查，绿色节点由本地程序校验和写入。

  1. 1 手动或 21:00 触发

    两种入口只在本地创建严格请求，共用后续 Workflow。

  2. 2 变化预检

    没有实质输入变化时，可以 0 次模型调用结束。

  3. 3 Scout 找候选

    先判断是否真的描述你的偏好、判断/工作方式或变化张力，再选择关系或停止。

  4. 4 Workflow 查证

    读取目标、搜索历史、形成带来源的证据包。

  5. 5 Judge 定稿

    基于已查到的材料提交 patch，或决定保留现状。

  6. 6 校验并入库

    来源、引文、版本、用户控制全部通过后原子写入。

Agent 判断 Workflow 执行 本地确定性规则
理解已更新

Agent 提交的新版本通过全部来源与写入校验。

本次没有更新

没有实质变化，或调查后证据仍不足；旧版本继续保留。

安全停止

预算、模型、版本或校验异常；本轮不写入，原始记录不变。

03 · 职责分工

智能放在判断上，控制留在流程里。

这个版本保留了 Agent 的动态选择能力，同时把文件、工具、预算和最终写入交给可验证的 Workflow。

Agent

判断“该不该变”

Scout、Search Planner 和 Terminal Judge 分阶段完成候选、调查与最终结论。

  • 判断有没有长期候选
  • 关联一条已有理解
  • 提出需要检索的方向
  • 决定提交或停止
Workflow

把调查做成可控步骤

程序执行 Agent 选择的读取与搜索，把真实结果整理成 Agent 可以引用的证据包。

  • 只读目标理解与历史记录
  • 执行有次数上限的搜索
  • 登记来源、日期、原文和引用 ID
  • 限制回合、工具和修正次数
Local Guard

决定“能不能写”

本地校验器不评判文案好不好看，只判断它是否满足证据、安全和版本合同。

  • 拒绝伪造或不一致的引用
  • 保护用户编辑和删除
  • 拒绝并发覆盖与旧版本写入
  • 只写一个主题的一次新版本
Agent 有两次真正关键的产品判断。

第一次决定调查什么；第二次决定调查完后是否值得改变长期理解。

new

形成此前不存在的新理解。

reinforce

新记录继续支持已有理解。

revise

当前方向变化，需要修订旧理解。

tension

新旧证据同时成立，保留张力。

04 · 产品验收

怎样判断这次 Agent 做得对不对？

不要只看“有没有写入”。正确的保留现状同样是有效结果。按下面六个问题逐项判断，更接近真实产品质量。

1

候选选对了吗？

近期内容是否真的出现了长期方向、重复原则、修订信号或需要保留的张力？

一次性安排被写成长记忆，属于误判。

2

关联的旧理解对吗？

revise、reinforce、tension 是否绑定了同一决策范围内的旧理解？

已有同主题理解却重复 new，需要警惕。

3

必要时查历史了吗？

关键变化信号落在近期窗口之外时，Agent 是否发起了有信息增益的检索？

工具数量不代表质量，关键看是否补上证据缺口。

4

结论忠于证据吗？

最终 statement、scope、正向依据和反向依据是否与原文一致，是否遗漏明显反例？

文字流畅不能替代来源正确。

5

用户控制被尊重了吗？

用户编辑是否保留？删除的同一记忆是否保持删除？并发变化是否安全停止？

覆盖用户操作，即使判断合理也属于产品失败。

6

成本与终态合理吗？

调用、搜索和修正是否解决了问题？最终是否明确为 updated、no_change、insufficient 或失败？

“请求已保存”只代表处理中。

可以判为做对

结果类型合理，证据能追溯，目标与版本正确，用户删改被保留；需要搜索时确实补到了关键材料。

需要记录为问题样本

漏掉明确变化、写入一次性内容、绑定错主题、搜索无关、遗漏反例，或虽然安全停止但反复无法完成同类任务。

06 · 实际使用

你现在可以这样用。

需要时使用“现在整理”，希望固定运行时再开启 21:00 计划。每次核对依据和最终变化，把正确更新、正确不更新、漏判和误写留作产品样本。

1

打开“关于我”

在 Chrome 新标签页打开右侧面板。阅读已有理解与依据不会调用 API。

2

立即整理或保存每日计划

点击“现在整理 / 检查最近 14 天”，或开启每日 21:00 计划。“计划已保存”不代表调度已执行。

3

等待明确终态

看到“理解已更新”“本次没有更新”或明确失败后，再评价本次结果；处理中状态不算完成。

4

核对依据与变化

检查候选、旧理解、历史搜索、原文依据和最终文案。必要时使用卡片菜单编辑或删除。

5

把异常当作产品样本

如果漏判、误写或调查方向不合理，记录当时的终态和可见证据，不需要反复点击碰运气。

编辑和删除怎样工作？

编辑和删除由本地用户操作流程保存，不需要新的 DeepSeek 判断，也不会修改原始日记。

  • 编辑：卡片右上角“···” → 编辑 → 保存修改。
  • 删除：卡片右上角“···” → 删除 → 确认删除。
  • 等保存提示消失或页面重新投影后，再关闭手动整理。
技术预算与安全上限
  • 最多 5 个模型回合、5 次受控工具动作。
  • 最多 2 个初始查询、2 次追加搜索；每次最多 5 条结果。
  • patch 校验失败后最多修正 1 次。
  • 一次任务只处理 1 个主题、最多写入 1 个 patch。
  • Token 执行停止阈值为 40,000，Prompt 字符上限为 180,000。

40,000 是模型返回后的执行停止阈值。已经发生的 Provider 调用可能让累计 Token 超过该数值；越界结果不会继续执行工具或写入。

命令行开启、查看与关闭

页面已提供主要产品入口。以下命令用于状态检查或人工开关；它们本身不调用模型。

# 查看状态
python3 ~/AISecretary/.context-agent/runtime/context_agent.py agent-status \
  --vault ~/AISecretary

# 开启手动整理
python3 ~/AISecretary/.context-agent/runtime/context_agent.py agent-enable \
  --vault ~/AISecretary \
  --confirm enable-remember-agent-v1

# 关闭手动整理
python3 ~/AISecretary/.context-agent/runtime/context_agent.py agent-disable \
  --vault ~/AISecretary \
  --confirm disable-remember-agent-v1

# 查看每日 21:00 配置
python3 ~/AISecretary/.context-agent/runtime/context_agent.py agent-schedule-status \
  --vault ~/AISecretary

# 开启 / 关闭每日 21:00 计划
python3 ~/AISecretary/.context-agent/runtime/context_agent.py agent-schedule-enable \
  --vault ~/AISecretary --confirm enable-remember-agent-daily-21
python3 ~/AISecretary/.context-agent/runtime/context_agent.py agent-schedule-disable \
  --vault ~/AISecretary --confirm disable-remember-agent-daily-21

关闭不会强制中断已经进入 Provider 的调用。需要关闭时，先等待当前核对或修改完成。

当前产品结论

目标产品形态是“随时整理 + 每日 21:00”的 Agentic Workflow MVP。

核心路径能够运行，Agent 在关键节点做判断，Workflow 能安全查证与写入，用户保留最终修改和删除权。 当前工作区为 Prompt v1.22 / Workflow v1.13，并绑定 stable-new identity v1.1 与 terminal gate v1.0；两个冻结合成 case 的真实 DeepSeek v4 有限验收已经通过。安装、开启、Chrome、真实用户 Vault 和 21:00 自然触发仍需分别验收。
