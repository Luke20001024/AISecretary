## 0. 统一产品叙事口径

本文遵循 [Memento 产品叙事统一口径](../MEMENTO_PRODUCT_NARRATIVE.md)。MVP 主要交付 **“接住正在发生的意图”** 与 **“长期理解你的形状”**：从原始记录、逐条整理、每日归并，一直形成认知地景和可修订的长期理解。

第三项价值统一表述为 **“让每个 AI，都从同一个你开始”**，产品能力名称为 **“可调用的个人记忆”**。当前版本只提供这项能力所需的本地事实、长期理解和投影基础；外部 AI 的产品化接入与真实任务回流需要单独验收。

## 1. 一句话定义

Memento 认知秘书持续接住用户主动留下的记录，逐条给出可核对的整理回执，每天把这些内容归并为可用记忆与关系，再以原文证据更新长期理解和认知地景。

主页只回答两个核心问题：

1. 她现在怎样理解我，这些理解最近发生了什么变化；
2. 我今天留下的每条内容被整理成了什么，又进入了哪里。

## 3. 产品目标

### 3.1 MVP 必须完成

跑通并可审计下面这条纵向链路：

```text
原始记录
→ 逐条整理回执
→ 每日归并与每日总结
→ 可用记忆与正式关系
→ 长期理解
→ 认知地景
→ 用户反馈与后续重算
```

完成后，用户应当能够：

1. 保存一条记录后立即看到“原文已保存”，随后看到逐条整理状态与结果；
2. 从任何整理结果、记忆点、关系或长期理解回到对应原文；
3. 手动归并当天内容，也可以启用每日 21:00 计划；
4. 在主页上看到已提交长期理解形成的地景和今天整理后的记录；
5. 对逐条整理选择“正确、改一下、仅保存原文”，对可用记忆、正式关系和长期理解执行修改或删除；
6. 在任一 AI 或投影步骤失败时继续找回原文，并看到上一版可信结果。

### 3.2 产品原则

- **原文先于解释**：原文先落盘，AI 失败不能影响保存结果。
- **即时回执与每日判断分速运行**：逐条整理追求及时可见；跨记录关系和长期理解在每日归并中谨慎提交。
- **候选与正式结果分层**：即时候选不能直接成为可用记忆、正式关系或认知峰。
- **Agent 判断，Workflow 控制**：Agent 决定语义；Workflow 负责权限、检索、状态、校验、版本和写入。
- **地景只做投影**：视觉层不推断人物，也不反向改写记忆。
- **用户版本优先**：用户修改、仅保留原文和删除动作在后续运行中持续生效。
- **没有新证据就保持安静**：不为制造活跃感而生成长期变化。

## 4. MVP 范围

| 模块 | v0.9.0 合同 | 用户可见结果 |
|---|---|---|
| 原始记录索引 | 为新记录分配稳定 `record_id`；对已有记录可重建索引；AI 只读原文 | 原文已保存、时间、来源、附件入口 |
| 逐条整理 | 识别内容类型、主题/对象、用户与内容的关系、认知状态、用途和候选记忆 | 一句整理结果、状态、候选主题、校准动作 |
| 每日归并 | 去重、多主题拆分、跨记录关联、反例/边界检查；形成一次原子日级提交 | 今日形成的可用记忆、关系、待校准项 |
| 每日总结 | 复用 Daily Review 的日期、Prompt 与冲突安全提交能力；把日级结果纳入主页摘要 | 当日总结、行动线索、未解决问题 |
| 可用记忆 | 从一条记录形成零个、一个或多个可引用记忆点 | 记忆点及其原文依据 |
| 正式关系 | 提交支持、反例、修订、适用边界和同主题关系 | 点与峰的连接、关系说明 |
| 长期理解 | 复用 Agent V1 的调查、证据门、不可变 revision 与用户 action | 新增、强化、修订、张力或无变化 |
| 认知地景 | 由正式对象确定性生成浅色 2D 地景；提供等价列表视图 | 山峰、记忆点、关系线、近期变化 |
| 主页 | 上半部认知地景，下半部今日整理记录，统一右侧详情栏 | 每天打开即可理解当前状态 |
| 反馈 | 逐条正确/完整编辑/仅保存原文；记忆/关系 edit/delete；长期理解修改/删除 | 主页只追加用户 action；本地 Worker 校验并物化，用户版本优先于并发模型结果 |
| 手动归并 | 主页只为浏览器当地当日写入不可变请求；后台 Worker 执行 | 显示请求已保存、处理中和有限终态；浏览器 0 Provider/CLI 调用 |

### 4.1 MVP 的认知地景边界

- 山峰只对应一条已提交且当前 active 的长期理解。
- 实心点只对应已进入某个日级正式提交的可用记忆。
- 等待归并的候选内容只在今日记录区表达，不进入当前正式地景。
- 连线只来自正式关系；候选关系不进入默认地景。
- 山峰高度表达经校验证据积累，不表达人格强度、重要性或真实性。
- 峰间位置用于稳定排版；视觉距离不表示关系、相似性、语义矛盾或重要程度，也不作为任何事实对象的输入。
- 只有正式连线表示已经校验并保存的关系。稳定 hash 只为新峰提供初始位置种子，不承载关系语义。
- Projector 必须对没有直接正式边、也没有通过同一条 active reusable memory 形成两跳正式关系的峰执行确定性避碰；上一版仍满足避碰边界的安全坐标优先保留。
- 存在直接正式边，或通过同一条 active reusable memory 形成两跳正式关系时，相关峰可以局部接近；允许接近不使视觉距离成为事实。
- 正式关系撤回后，如果原坐标使无关系峰产生点击热区或 KDE 布局碰撞，Projector 必须确定性重排碰撞点，并保留其他安全坐标。

### 6.1 上半部：她现在怎样理解我

默认展示当前可信地景和一行文字摘要：

> 当前 4 项理解 · 1 项近期变化 · 2 项仍在观察

点击山峰后，侧栏按“当前理解 → 最近变化 → 支持与反例 → 相关记忆 → 原文 → 版本与校准”展示形成链路。点击点或关系线时，侧栏切换到对应对象，但不离开主页。

### 6.2 下半部：今天的内容被整理成了什么

每条记录至少显示：

- 时间与来源；
- 一句整理结果；
- 内容类型；
- 主题或对象；
- 后续用途；
- 当前处理状态；
- 关联的零个、一个或多个长期理解。

原文不在列表中展开。点击记录后，侧栏依次展示逐条整理、候选或正式记忆、关联关系、原文与校准动作。

## 7. 核心用户旅程

### 7.1 保存并看到逐条整理

```text
用户通过现有 Service 留下一条内容
→ 原文写入成功
→ 首页立即出现“原文已保存”
→ Record Interpreter 读取这一条授权文本
→ 返回逐条整理回执
→ Workflow 校验来源与合同
→ 首页显示“已初步整理，等待今日归并”
→ 用户可选择正确、改一下、仅保存原文
```

逐条整理可提出候选主题、候选记忆和候选关系；它不能直接新增长期理解或认知峰。

### 7.2 手动或 21:00 每日归并

```text
冻结当天有效记录与回执清单
→ 补齐尚未完成的逐条整理
→ 校验全部当前 active records 均已被合法回执、可信 no_candidate 或用户终态覆盖
→ 去重与多主题拆分
→ 查回相关历史和当前长期理解
→ 生成候选可用记忆与候选关系
→ 确定性校验并原子提交日级 bundle
→ 生成或更新 Daily Review
→ 有实质长期变化时进入 Agent V1 Memory Judge
→ 更新长期理解
→ 重建认知地景与主页投影
```

点击“归并今天”后，浏览器先写入只含日期与身份的不可变本地请求，并等待精确绑定的本地结果。事件 Worker 复读总开关，只接受当天请求，再以 `manual` trigger 进入与 `scheduled / recovery` 相同的日级 Orchestrator 与提交合同。页面本身不调用 Provider 或 CLI。

完整覆盖闸门的终态口径：全部当前记录为 `no_candidate` 时返回 `no_candidate`；全部为 `original_only / tombstone` 时返回 `no_change`；`ready / needs_review` 与 `no_candidate` 混合时只归并前者。存在任一失败或尚未终态的 active record 时，不部分提交。

### 7.3 从地景回到原文

```text
点击山峰、记忆点或关系线
→ 打开统一侧栏
→ 查看形成链路与适用范围
→ 选择某条依据
→ 定位原始记录及附件
```

任何图形对象都必须提供等价文字入口。

### 7.4 校准并回流

```text
用户通过合法 UI/本地 action client 提交反馈
→ 投影读取尚未物化但已验证的 action watermark
→ Worker 校验 target revision 与 hash
→ 物化新的不可变 revision 或 tombstone
→ 受影响的每日结果、关系、长期理解和地景按依赖关系重建
```

“仅保存原文”会停止该记录进入本次及后续自动归并；同一 `record_id` 后续 source edit 也不会自动恢复整理。恢复自动整理不在 MVP 内。

## 8. 页面与运行状态

### 8.1 记录状态

| 状态 | 页面文案 | 允许动作 |
|---|---|---|
| `raw_saved` | 原文已保存 | 查看原文 |
| `processing` | 正在整理这一条 | 查看原文 |
| `ready` | 已初步整理，等待今日归并 | 查看结果；正确、改一下或仅保留原文 |
| `needs_review` | 有一处需要你确认 | 查看依据；正确、改一下或仅保留原文 |
| `no_candidate` | 已检查，本条没有形成可归并内容 | 查看原文 |
| `failed` | 原文已保存，整理尚未完成 | 通过 Worker/CLI 重试；已有合法回执时可仅保留原文 |
| `original_only` | 仅保留原文 | 查看原文 |
| `merged` | 已进入今日归并 | 查看记忆、关系与原文 |

### 8.2 每日归并状态

| 状态 | 页面表现 |
|---|---|
| 未到计划时间 | 只显示下一次计划，不表示失败 |
| 待归并 | 显示可处理记录数；可在主页点击“归并今天” |
| 运行中 | 保留上一版地景；显示当前阶段与已完成数量 |
| 已完成 | 显示新增记忆、关系、长期变化或“没有改变长期理解” |
| 已完成但有警告 | 日级结果可用；明确指出长期判断或地景仍沿用上一版 |
| 失败 | 原文与已提交对象保持可用；提供重试或诊断入口 |
| 输入已变化 | 本次结果作废并标记 stale，不覆盖新输入 |

### 8.3 主页降级状态

- 今天无记录：认知地景继续显示，下半部安静提示“今天还没有记录”。
- 没有长期理解：显示记录点和“仍在积累”，不生成空山峰。
- 地景生成失败：展示上一版地景和当前文字列表。
- 目录权限失效：显示恢复访问，不把缺数据呈现为空记忆。
- Provider 不可用：原文、历史整理、长期理解和地景保持可读。
- 用户删除理解：当前地景立即隐藏该峰，原始记录继续存在。

## 9. Agent 与 Workflow 职责

| 阶段 | Agent 负责 | Workflow 负责 |
|---|---|---|
| 逐条整理 | 类型、主题、对象、关系、状态、用途和候选拆解 | 记录身份、授权文本、调用预算、Schema、来源 hash、状态和落盘 |
| 每日归并 | 去重语义、多主题拆分、候选记忆与关系、冲突检查 | 冻结 manifest、历史检索、引用物化、批次提交和幂等 |
| 长期理解 | 调查候选，判断新增、强化、修订、张力或停止 | 复用 Agent V1 的工具、证据、tombstone、CAS 与 commit |
| 地景 | 不参与视觉判断 | 从正式对象生成稳定坐标、等高线、点线和文字列表 |
| 用户反馈 | 后续运行读取用户版本 | 保存不可变 action、检查并发、重建依赖投影 |

## 10. 产品边界与信任规则

- 地景只表达用户主动记录形成的局部理解，不代表完整人格。
- AI 摘要、逐条整理文案和 Daily Review 不能独立证明一条长期理解；最终证据必须回到原文。
- 用户的文字、截图 OCR 和语音转写可以成为授权文本；原始图片、音频和非允许目录资产默认不发送给 Provider。
- 页面不展示模型隐藏思维过程，不持久化自由文本推理。
- 打开主页、地景、侧栏或原文不应触发模型调用。
- 计划“已保存”不等于当天已经执行；运行状态必须单独展示。
- 任何失败都不能覆盖上一版可信长期理解或地景。

## 11. 验收与 Definition of Done

只有下列项目全部通过，才可以称为“认知秘书 MVP 已真实可用”。每项实测结果记录在 [发布清单](RELEASE_CHECKLIST.md)。

### 11.1 端到端能力

- [ ] 新记录得到稳定 `record_id`，重复扫描不会生成第二条记录。
- [ ] 原文写入成功后，主页在不等待 AI 的情况下出现 `raw_saved`。
- [ ] 逐条整理完成后可看到结果、状态和候选归属，并能回到准确原文。
- [ ] 一条记录能够形成零个、一个或多个可用记忆，并能关联零个、一个或多个长期理解。
- [ ] `no_candidate` 在重放和 Home 重建后仍为无 receipt 终态；同一已知 Schema 拒绝最多只有 1 次附加重试。
- [ ] 手动归并与 21:00 归并共享同一合同；同日重复触发不会重复提交。
- [ ] 每日归并只在全部当前 active records 完整覆盖后原子提交可用记忆、正式关系和日级摘要；未覆盖时不部分提交。
- [ ] 只有 Agent V1 成功提交 active memory revision 后才生成或改变山峰。
- [ ] 点击峰、点、关系和下方记录，能在同一侧栏互相定位并查看形成链路。
- [ ] 用户逐条校准、可用记忆/关系 edit/delete 和长期理解 edit/delete 会持续影响后续运行。

### 11.2 数据与恢复

- [ ] AI 和迁移工具不修改原始日级记录和原始附件。
- [ ] 每个正式对象均绑定有效 `record_id`、source span、source hash 和 revision。
- [ ] 来源、目标 revision 或用户 action watermark 变化时，提交返回 stale 且 0 正式写入。
- [ ] Provider 失败、非法 JSON、预算耗尽、进程中断和地图投影失败均有恢复测试。
- [ ] 日级批次只有在 commit manifest 原子落盘后才对投影可见。
- [ ] `home-projection` 和地景快照可以删除并从正式对象重建。
- [ ] 原文已保存但事件丢失时，reconcile 能补建索引和待处理任务。

### 11.3 页面与产品语言

- [ ] 主页第一屏清楚区分认知地景、今日整理状态与今日记录。
- [ ] 每个视觉对象都有明确数据含义和等价列表视图。
- [ ] 主页明确说明峰间远近没有关系或重要程度语义，只有正式连线表示已校验关系，山峰高度只表示证据积累。
- [ ] 无正式关联的峰不会因 hash 种子形成位置冲突；关系撤回后只确定性重排冲突点，其他安全坐标保持稳定。
- [ ] 今天无记录、无长期理解、部分失败和权限失效均有专门状态。
- [ ] 页面沿用浅色底板、墨色文字、发丝线、克制雾蓝和右侧深阅读方式。
- [ ] Token、hash、模型调用、内部 run step 和诊断细节不进入主页主叙事。
- [ ] 复制给 AI、每日历史、归档和设置仍可到达，但不争夺主页注意力。

## 12. 指标与待验证假设

### 12.1 运行指标

- 新记录索引成功率；
- 逐条整理完成率、P50/P95 可见延迟和重试率；
- 每日归并成功率与 `committed_with_warnings` 比例；
- 重复对象、无效引用、stale 和恢复成功率；
- 每次逐条整理、每日归并和长期判断的调用、Token 与成本。

### 12.2 产品指标

- “正确、改一下、仅保存原文”的比例；
- 每日记录进入可用记忆的比例；
- 可用记忆形成正式关系和被长期理解引用的比例；
- 长期理解被修改、删除和误生成的比例；
- 用户从地景返回原文的次数；
- 每周帮助找回信息、进入决定或修订判断的历史复用数。

### 12.3 待验证假设

本节是产品假设，不作为 v0.9.0 已验证结论。

- 逐条回执可降低用户对“记录被 AI 如何处理”的不确定感。
- 即时整理与每日归并分速运行，可同时保留反馈及时性和长期判断的连续性。
- 首页先显示地景感受、点击后再展开形成链路，可让长期理解更易进入日常使用。
