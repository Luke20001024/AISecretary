# Memento 产品演进规划

> 从“记录闭环”走向“理解与使用闭环”。
>
> 统一文案基线：[Memento 产品叙事统一口径](MEMENTO_PRODUCT_NARRATIVE.md)

## 1. 产品命题

Memento 聚焦一条从主动记录到长期理解、再回到真实工作的个人记忆链路。它要验证的是：

> 用户主动确认的少量 Context，能否比系统自动观察的大量 Context 更准确、更可信，也更有长期价值。

对外表达统一为三项价值：

1. **接住正在发生的意图**
2. **长期理解你的形状**
3. **让每个 AI，都从同一个你开始**

内部产品定义：

> 一份由用户持有和治理、能够按任务带入不同 AI 的可调用个人记忆。

## 2. 首要目标用户

第一阶段只面向同时满足以下特征的 Mac 知识工作者：

- 高频使用 Codex、ChatGPT、Claude 或其他 AI；
- 在聊天、浏览器、文档、代码之间频繁切换；
- 经常需要重复解释项目背景、判断依据和个人偏好；
- 在意个人数据所有权与 AI 对自己的错误理解。

优先场景：产品经理、独立开发者、研究者、设计师的项目判断与工作 Context。

暂不从“理解完整的人”切入。先验证项目判断、工作偏好和已确认约束，再逐步扩展到价值、兴趣与成长方向。

## 3. 核心体验原则

### 3.1 0 摩擦不等于 0 确认

- 不离开当前窗口；
- 不重新复述 Context；
- 不要求先分类和整理；
- 保留一次明确触发，作为“这件事值得记住”的信号。

### 3.2 事实、解释和反馈分层

- 原始事实保持原样；
- AI 只能提出暂时理解；
- 用户反馈单独保存，不覆盖原始事实；
- 长期理解必须能够返回证据、版本与修改来源。

### 3.3 在使用中校准，不制造 Review 待办

- 不要求用户每天批量审核所有 AI 判断；
- 只有当理解足够新颖、存在冲突、风险较高或即将影响回答时才出现；
- 每次只呈现一个局部理解；
- 完整管理页只承担搜索、审计、导出和撤回。

### 3.4 越接近“我是谁”，确认要求越高

- 可直接核对的任务事实可以暂存；
- 工作偏好需要在相关任务中验证；
- 价值、性格、关系、情绪和身份判断必须明确确认；
- 未经确认的敏感推断不能成为长期记忆。

## 4. 记忆生命周期

```text
原始事实
  ↓
理解候选（AI 提出，带证据与不确定性）
  ↓
暂时理解（只在相关场景中出现）
  ↓
使用中验证（说明为何使用）
  ↓
用户确认 / 限定 / 纠正 / 拒绝
  ↓
长期 Context（可修订、可撤回、可被新证据替代）
```

推荐的用户回应：

- 是的；
- 只是这次；
- 只在某种情况下；
- 我想改一句；
- 不要记住。

## 5. 近期路线图

### P0 · 建立验证基线

目标：能够回答用户是否持续记录、是否回看，以及 Context 是否被再次使用。

- 定义本地、可导出的匿名使用事件；
- 记录触发、回看、复制给 AI、理解候选回应和撤回行为；
- 不记录正文、图片、录音或 AI 理解内容；
- 建立 8～12 名目标用户的四周测试；
- 访谈记录“这次 Context 帮助了什么”，而不只询问满意度。

验收条件：

- 可以计算每周活跃记录天数；
- 可以识别一条旧 Context 是否在未来任务中被使用；
- 所有研究数据均可由用户查看、导出和关闭。

### P1 · Re:member 卡片 MVP

目标：验证用户是否愿意在自然时机回应一个局部理解。

- 从同一天或最近数天的多条事实中生成至多一个理解候选；
- 候选必须包含原始证据链接、范围和不确定性；
- 支持“是的 / 只是这次 / 限定范围 / 改一下 / 不要记住”；
- 用户修改原样保存，AI 解释和用户反馈分别存储；
- 敏感或身份类判断默认禁止生成；
- 新标签页最多出现一张卡片，并设置打扰频率上限。

验收条件：

- 用户能够在 10 秒内完成一次回应；
- 用户能理解“确认事实”和“确认 AI 解释”的区别；
- 拒绝后候选不再出现；
- 每条已确认理解都能回到原始事实。

### P2 · 使用中校准

目标：证明过去的 Context 能帮助一个未来任务。

- 一键生成与当前任务相关的 Context 包；
- AI 使用已确认理解时展示“基于什么”；
- 支持“本次不使用”“以后不要使用”和当场纠正；
- 优先实现只读本地检索，再考虑自动写回；
- 为单条 Context 增加主题、项目、时间和可用范围。

首个杀手场景：

> 用户昨天在聊天和文档中做出一个产品决定，今天打开 Codex 时，可以直接带入决定、依据和已确认约束，不必重新解释。

验收条件：

- 至少一半测试用户发生过一次旧 Context 的真实复用；
- 用户能判断某次回答使用了哪些个人 Context；
- 用户可以在不删除原始事实的情况下撤回 AI 使用权限。

### P3 · 局部长期理解

目标：验证理解能否随着新证据变化，而不是形成静态标签。

- 从产品判断、工作方式等低风险侧面开始；
- 新证据只触发相关侧面的局部更新；
- 允许反例、矛盾和多个适用条件并存；
- 显示理解版本、修改原因和用户确认记录；
- 长期未使用、低置信度候选可以自然淡出；
- 未经用户确认的推断不能进入可调用的个人记忆。

### P4 · 可调用的个人记忆

目标：让每个 AI 都从同一个你开始。个人事实与长期理解由用户持有，并按任务范围带入不同模型。

- 提供只读本地 MCP 或同等检索接口；
- 支持按项目、主题、时间和敏感级别选择调用范围；
- 支持 Codex、Claude、ChatGPT 与本地模型；
- 记录某个 AI 何时读取了哪些 Context；
- 写回和自动修订必须单独授权。

## 6. 暂不优先

在 P1、P2 得到正向验证前，不优先投入：

- 多设备同步；
- 全量后台录屏；
- 更复杂的照片时间线；
- 更多 Daily Review 模板；
- 自动生成完整人格画像；
- 团队与社交功能；
- 复杂 HTML 归档自动化；
- 大量视觉细节完善。

每日第一帧作为情感化签名能力保留，但暂不作为核心增长方向。

## 7. 衡量方式

### 北极星指标

**Weekly Reused Contexts：每周在未来任务中被重新使用，并帮助用户的历史 Context 数量。**

### 辅助指标

- 每周主动记录天数；
- 从首次安装到第一次成功记录的时间；
- 从记录到第一次回看的时间；
- 理解候选的确认、限定、纠正、拒绝比例；
- 已确认 Context 的未来使用率；
- 使用 Context 后的再次纠正率；
- 四周持续使用率；
- 用户能够明确描述的“幸好它记住了”事件数。

### 继续信号

- 超过一半测试用户四周后仍持续记录；
- 多数用户至少发生一次有明确结果的 Context 复用；
- 用户会主动纠正理解，因为他们在意它将来如何被使用；
- 用户愿意将已确认 Context 提供给第二个 AI。

### 停止或转向信号

- 用户只因新鲜感在前几天记录；
- Daily Review 被阅读，但从未进入后续任务；
- 用户喜欢理念，却无法说出具体使用时机；
- 理解候选持续被忽略，且没有更自然的出现时机；
- 产品价值只在创作者本人身上成立。

## 8. 下一版本建议范围

下一版本只聚焦以下最小闭环：

```text
多条原始事实
  → 一个有依据的理解候选
  → 用户一次轻量回应
  → 在后续真实任务中透明使用
  → 用户可以当场再次纠正
```

完成这个闭环，Memento 才真正从记录工具跨越为个人 Context 产品。在此之前，不用急于扩大能力边界。
