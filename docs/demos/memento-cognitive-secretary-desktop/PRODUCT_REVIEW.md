# Memento「认知秘书桌面」产品复盘

> 快照日期：2026-08-17
> 本文把当前能力事实、产品判断和 Demo 假设分开记录。

## 1. 当前产品已经具备什么

| 产品层 | 已有能力 | 用户现在从哪里进入 |
|---|---|---|
| 原窗口记录 | 文字、备注、标签、截图与 OCR、语音 | macOS Service，发生在原来的应用窗口 |
| 本地事实层 | 按日 Markdown 与原始资产 | `~/AISecretary`；Obsidian 可作为可选的搜索与编辑器 |
| Chrome 新标签页 | 今日记录数、Prompt 范围与风格、复制给 AI、90 天记录带、标签筛选、当天记录流 | 新标签页主页 |
| 长期人物理解 | 反复出现、最近变化、仍在权衡；逐字依据与反例；编辑和删除 | 右侧「关于我」抽屉 |
| 整理控制 | 立即整理最近 14 天、每日 21:00 计划 | 「关于我」抽屉 |
| 每日回顾 | 每日第一帧、Daily Review、处理状态 | 右侧「每日总结」抽屉 |
| HTML 归档 | 导入、查看和删除单文件 HTML | 右侧「归档」抽屉 |
| 运行审计 | 模型调用、工具动作、Token、成本、终态 | 「关于我」的二级详情 |

本机只读核对结果：仓库与已安装 Chrome 扩展的 `dashboard.html`、`dashboard.css`、`dashboard.js`、`remember-agent-v1-library.js`、`manifest.json` 逐文件一致；Re:member 总开关有效，每日 21:00 计划配置有效。事件任务只监听 `requests` 与 `user-actions`，独立计划任务使用 `StartCalendarInterval 21:00`。当前计划任务的最近退出码为 2，日志记录一次来源变化导致的 `stale`；现存 7 条请求均为 `manual`。因此，自动整理已安装并配置，21:00 自动闭环仍未由当前本机证据证明成功。

当前代码没有“问过去的自己”或自然语言语义问答入口。该能力若出现在未来方案中必须标注 `[猜测]`，本轮三版 Demo 不把它伪装成现成功能。

## 2. 现有版本的主要结构问题

- 新标签页仍把“复制今天 → AI”放在首要位置。
- 已经具备依据、反例、版本和用户控制权的“她眼中的我”仍藏在右侧抽屉。
- 记录、长期理解、每日回顾和归档被分成四个入口，用户不容易形成同一个产品心智。
- “关于我”抽屉同时承载人物理解、运行控制、计划、诊断和旧版兼容说明，阅读层与运维层混在一起。

## 3. AI Native 产品判断

[猜测] Memento 最有区分度的两项资产是：

1. 在原场景低摩擦留下、仍由用户拥有的事实记录；
2. 从这些事实形成可追溯、可修订、可删除的长期理解。

[猜测] 「认知秘书桌面」的主要目标是：

> 每次打开新标签页，用户能在数秒内看见“我今天留下了什么、Memento 当前怎样理解我、这份理解最近是否需要我介入”，然后继续原来的工作。

[猜测] 用户侧需要感受到四件事：

1. **事实还在**：今天的原始记录清楚可见，没有被 AI 文案覆盖。
2. **理解有来路**：任何人物理解都能回到日期、来源、逐字依据和反例。
3. **理解会变化**：新版、旧版、适用范围和未知边界可以被查看。
4. **用户有最终控制权**：可以修改、删除、手动整理或关闭计划。

## 4. AI、Workflow 与用户的责任

| 角色 | 责任 |
|---|---|
| 用户 | 主动记录；决定是否整理；修改或删除理解 |
| Agent | 判断有没有人物相关候选；关联旧理解；决定是否查历史；提交一个更新或停止 |
| Workflow | 读取授权记录；执行有界检索；物化逐字证据；控制预算和次数 |
| 本地校验器 | 核对来源、引文、版本、并发与用户删改；安全写入或保留旧版 |
| 主页 | 展示已验证结果、依据和用户控制权；不展示模型隐藏推理 |

## 5. 新主页的信息优先级

### 首屏

1. **她眼中的我**：一次突出一条当前最值得阅读的理解。
2. **今天留下的记录**：数量、2 至 3 条预览、日期与来源。
3. **90 天记录痕迹**：只表达每日记录数量。
4. **整理状态**：已更新、无变化、证据不足、失败；以及“现在整理”。

### 一次滚动或详情层

- 全部理解分组；
- 依据、反例和版本史；
- 当天完整记录流与标签；
- 每日总结与第一帧；
- 编辑和删除。

### 工具层

- 复制给 AI 与 Prompt 组合；
- HTML 归档和导出；
- Token、成本与完整轨迹；
- 总开关、调度诊断与旧流程兼容信息。

## 6. 三版共同内容合同

三版只改变视觉语言和信息编排，以下产品语义完全一致：

- 产品名为 Memento，页面身份为“认知秘书桌面”；
- 核心两区为“她眼中的我”和“今天留下的记录”；
- 当前理解包含表述、适用范围、更新时间、依据数、反例数和来源状态；
- 用户可查看依据、编辑、删除、现在整理，并查看计划状态；
- 今日区包含记录数、记录预览、日期、来源、标签和 90 天记录带；
- 二级入口包含每日总结、完整记录、归档、导出和整理详情；
- 所有 Demo 使用相同演示数据；
- 所有 Demo 标明“完全离线 · 演示数据 · 操作只在当前页面模拟”。

## 7. Demo 不能虚构什么

- 计划已保存不能写成计划已经真实执行。
- 90 天记录带不能解释为情绪、自律、生产力或人格评分。
- 不使用人格完整度、了解度或置信度百分比。
- 图片只能作为品牌意象或明确的记忆锚点，不能被当作人物证据。
- 不生成健康、心理、身份、关系、能力评级或动机归因。
- 不宣称当前已有自然语言语义问答、跨 AI 同步或完整人格画像。
- 删除只能保证同一 `memory_id` 的确定性抑制，不能扩大为所有近义表达永久消失。

## 8. 产品验收假设

[猜测] 本轮 Demo 用以下标准判断方向是否成立：

- 5 秒内能说出页面同时服务“理解自己”和“回看今天”；
- 10 秒内能打开一条理解的依据；
- 10 秒内能找到“现在整理”；
- 无需展开详情就能区分“计划已保存”和“本轮已运行”；
- 今日记录仍拥有清晰视觉重量；
- 复制、导出和归档不再争夺首屏注意力；
- 三版的差异来自结构与视觉语言，功能和状态语义保持一致。

## 9. 本轮交付边界

本轮交付为 3 个完全本地、完全离线的高保真 Demo。它们不会读取真实 Vault，不会调用 DeepSeek，不会写入 Chrome 扩展，也不会创建真实 request、schedule 或 user-action。

Demo 中的编辑、删除、立即整理、计划开关和导出只改变当前页面内存状态，刷新后复原。这样可以完整比较产品体验，同时避免把视觉验证误写成生产功能验证。
