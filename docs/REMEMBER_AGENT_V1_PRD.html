00 / 产品决定

第一版做“会调查的理解 Agent”，不做换名字的固定流程。

Agent 的长期目标只有一个：维护一份有证据、能变化、由用户最终定义的“她眼中的我”。它可以决定本轮要核对什么、是否回看更早历史、是否寻找反例，以及证据不足时主动停止；但不能自由读取全部电脑、直接改原始记录、绕过用户删除，或不经本地校验写入长期理解。 这是一套有边界的自主性：模型负责调查策略，确定性代码负责权限、证据、预算、并发和落盘。模型只返回枚举 reason_code，不保存自由文本推理理由。
成功标准不是“用了 Agent 框架”。 同一批材料上，Agent 必须真的表现出不同的取证路径和停止决定，并在长期理解质量或不必要调用上优于固定工具链；否则应诚实保留为 Workflow。

02 / 目标与边界

V1 只证明一件事：自主调查是否产生更可信的长期理解。

G1

相关性

新记录出现时，Agent 能先定位受影响的既有理解，而不是重新概括用户全部记录。

G2

变化识别

Agent 能区分强化、新理解、范围修订、张力和证据不足，并允许不同方向并存。

G3

主动停止

一次性事件、噪音或证据不足时，Agent 能结束本轮而不是为了填满页面制造理解。

G4

可审计

用户能知道它查看了哪些范围、调用了什么工具、依据是什么、为什么没有更新。

G5

用户定义权

用户修改先以不可变 action 立即改变投影，再由 Worker 物化为新版本；用户删除后，同一 memory_id 与同一 exact semantic key 不能静默复活。

G6

可比较

与当前单次 Workflow 和固定工具链使用相同数据、合同与模型，单独测量 Agent 增益。

V1 包含V1 不包含原因
产品判断、工作方式、明确约束、低风险兴趣线索健康、心理、情绪、身份、关系、能力评级与动机归因越接近“我是谁”，证据与确认要求越高；V1 先验证低风险工作理解。
日级文本与已校准理解照片、音频、持续屏幕、传感器或其他 Vault 文件保持现有授权范围，避免把多模态扩张与 Agent 能力验证混在一起。
单 Agent、四个工具、有限回合多 Agent、长期后台自治、开放网页或任意本地工具先证明最小闭环，同时控制成本、隐私与失败面。
既有“她眼中的我”文章聊天输入框、虚拟形象、标签墙、多人对话产品核心是查看累积理解，不是增加一套对话产品。

04 / Agent 循环

每个节点都对应一种不能交给模型自由发挥的风险。

01 · START

建立任务

记录用户触发、目标日期、授权范围和运行预算。

必要性：让一次运行有明确边界，并可幂等重试。

02 · SNAPSHOT

冻结输入快照

收集最近 14 个自然日的授权记录、来源 hash、相关反馈与当前记忆版本。

必要性：避免调查过程中材料变化后仍提交旧结论。

03 · OBSERVE

识别值得核对的侧面

Agent 先判断本轮是否存在可能影响长期理解的信号。

必要性：不把每条新记录都提升成长期特征。

04 · PLAN

选择下一步

查看画像、检索历史、提交建议或结束，一次只选一个动作。

必要性：这里形成不同于固定工具顺序的真实自主性。

05 · ACT

调用白名单工具

本地控制器执行只读检索，并将结构化结果返回 Agent。

必要性：模型不能自行打开文件或扩大授权范围。

06 · REFLECT

判断证据是否足够

根据工具结果继续调查、寻找反例或主动停止。

必要性：让“证据不足”成为合法结果，而不是失败。

07 · VALIDATE

校验建议

代码核对 JSON、逐字证据、来源 hash、版本、隐私和预算。

必要性：模型建议不能等同于可写入事实。

08 · COMMIT

生成新版本并投影

通过 CAS 写入不可变 revision，再重建“她眼中的我”。

必要性：保证并发时不覆盖用户刚做的修改。

04.1 / 四个工具

工具越少，越容易证明每一次自主选择都有意义。

read_memory

查看当前已经怎样理解用户

按一个 memory_id 返回当前 active revision、适用范围、证据、反例与用户校准。

边界：只读；不能返回已撤回正文，也不能修改 profile。

search_history

有目的地回看更早历史

Agent 提供查询、时间范围和目的；本地检索只返回授权日级文本中的有限逐字结果及来源 hash。

边界：不浏览任意 Vault、不联网；缺失日期不当作反例。

finalize_patch

提交结构化修改建议

单次提交只允许 new、reinforce、revise 或 tension，并绑定证据、目标 memory_id 和 expected revision。

边界：非 new 操作必须先成功 read_memory，这由代码门检查；本地验证器通过后才可能落盘，Agent 不能删除或撤回记忆。

finish

明确结束本轮调查

模型可返回 no_change 或 insufficient_evidence；达到预算时由本地控制器写 budget_exhausted。三者都不制造内容更新。

边界：结束不修改 profile，也不能伪装成本轮已经更新。

04.2 / 决策权

Agent 自主决定调查；程序决定权限与落盘。

问题Agent 决定确定性程序决定用户决定
本轮关注什么先判断材料是否描述用户稳定偏好、判断/工作方式或变化张力，再选择候选；纯系统规格/运行状态应停止。只提供授权范围内材料，限制敏感主题。通过“现在整理”或 21:00 计划决定是否启动。
还要查什么选择查看既有理解、检索历史、寻找支持或反例。执行工具、限制范围与返回数量、记录工具轨迹。决定每日 21:00 计划是否开启；历史 backlog 不由 schedule 自动回填。
如何解释提出 new / reinforce / revise / tension 或停止。验证证据、Schema、版本、重复、敏感边界与来源一致性。可以随时修改表述、范围或删除整条理解。
写入什么只能提交 patch 建议。Worker 独占 revision 写权限，在锁内重算当前版本后写下一不可变 revision；失败则不写新版本。Dashboard 只写不可变 edit / delete action；投影立即生效，用户删除形成终态抑制约束。
花费多少在预算内决定是否继续调查。硬性限制回合、工具、字符、超时和调用次数并记录 usage；material gate 可 0 调用结束。决定手动触发与每日计划开关。
V1 首版预算合同；阈值合理性仍为 [猜测] 生产 Agent CLI 与 Worker 当前默认最多 5 次模型回合、5 次工具调用、40,000 total tokens、180,000 prompt 字符与 1 次 patch 提交。阈值在 Provider 返回后才能核对；如累计超额，该 completion 不继续执行工具或写 memory，也不再调用 Provider，终态为 budget_exhausted。通用 AgentBudget 和历史 preflight 仍有 3 回合 / 12,000 Token 的独立默认；不用当前生产 CLI 预算改写历史评测数字。

05 / 长期记忆

从“文案相同才合并”升级为稳定 memory_id 与不可变 revision。

memory_id: mem_<24 hex> revision: 3 status: active revision 3: operation: revise previous_revision_sha256: "..." run_id: arun_<24 hex> request_id: arq_<24 hex> user_action_id: null statement: "当前表述" scope: "适用范围" evidence: [...] counterevidence: [...] created_at: "..." user_action: id: uact_<24 hex> action: edit | delete base_revision: 3 base_revision_sha256: "..."

身份不随改写变化

memory_id 表示同一个局部理解；Agent 或用户修改表述、范围和依据时递增 revision，不重新生成一个同义标签。

历史版本不可覆盖

每个 revision 文件不可变；当前版本从连续 revision 链确定性派生，前端可以解释“什么时候、因为什么发生修订”。

用户操作优先

Dashboard 的 edit / delete 只写不可变 user action，不直接写 revision。投影立即叠加 action；Worker 在锁内把它物化为 user_edit 或 tombstone revision。

Agent 不自动销毁理解

发现反例时只能 revise 或 tension；撤回、删除与恢复权属于用户，来源失效由本地状态机处理。

迁移边界 当前 profile 的 ptag_* 仍是 exact statement + scope 的派生身份。Agent V1 不能就地把它冒充稳定记忆；需要显式迁移：为现有 active tag 建立初始 memory_id、保留原 response / feedback provenance，并在语义不确定时保持为两个独立对象。
近义复活仍是已知边界 稳定 memory_id 与 tombstone 只能确定性阻止同一对象和同一 exact semantic key 复活。换一种近义表述仍可能形成新的 key；V1 只能通过 read_memory、本地重复检索和评测降低风险，不能承诺完全拦截。
v1.6 stable-new 命名边界 new 只在唯一合格完整句跨至少两个不同日期文件逐字重复时派生；statement 逐字复制该句，scope 只能来自版本化 canonical trigger 映射。候选或映射不唯一、缺少 scope、命中排除语义或不安全文本时必须 finish，不得同义改写。这是稳定命名合同，不是语义去重或人格判定。

06 / 运行状态

每一轮都有清楚的中间态、终态和失败恢复。

request: pending→ run: running→ updated | no_change | insufficient_evidence | budget_exhausted | stale | error
终态含义对文章的影响是否计入成功更新
updated一个 patch 通过验证并提交新 revision。重新投影受影响段落。是
no_changeAgent 主动判断没有长期变化。保持原文，只更新最近核对时间与轨迹。成功运行，但不是内容更新
insufficient_evidence调查后证据仍不足。保持原文，不生成占位理解。成功停止，不是内容更新
budget_exhausted达到模型回合、工具调用或 Token 硬预算。保持原文，记录预算停止。否
stale来源、目标 revision 或用户反馈在运行中变化。保持原文；允许按新快照重试。否
errorProvider、解析、I/O 或本地校验失败。保持原文并给出安全错误。否
不可伪造成功 只有不可变 revision 已经原子提交，任务才能进入 updated。模型说“已更新”、生成 patch 或通过部分校验都不算完成。

07 / 隐私、成本与失败

Agent 增加的是选择能力，不是无限权限。

PRIVACY

出站最小化

Dashboard 不持 Key、不直连 Provider。只有本地控制器选定的近期增量、工具结果和必要记忆版本进入模型；密钥形状与敏感行先移除。

COST

每回合独立计费

本地快照、检索、hash 与投影不产生 API 成本；每次模型回合写 usage，任务汇总调用数、Token、缓存与计算成本。

FAILURE

失败不改当前理解

Provider 超时、非法动作、证据失效、CAS 冲突或预算耗尽都不会修改原始日记，也不会覆盖当前 active revision。

失败场景确定性处理前端反馈
模型返回未知工具或越权参数拒绝执行并记录 invalid_action；可在剩余预算内要求修正。不展示原始 Provider 内容；失败时保留旧文章。
Provider 调用中断，只留下调用前 checkpoint未知结果标记 unknown_attempt；若 Provider 或本地错误已明确，先写内部 resolved checkpoint 再写 response。两种情况都不对同一 request 自动付费重试。保留旧文章；内部 attempt marker 不作为用户工具轨迹展示。
证据 quote、行号或 hash 不匹配patch 校验失败；不写 revision。显示“来源已变化，需要重新核对”。
用户运行中修改或删除目标理解不可变 user action 立即改变投影；action watermark 或 target revision 校验失败，任务进入 stale。用户操作立即生效，Agent 结果不覆盖。
历史检索没有结果返回空结果而非补写背景；Agent 继续或 finish。轨迹可显示“未找到更早依据”。
达到预算调用前已达到阈值时停止新的 Provider 调用；若 Provider 返回后累计超额，则解析并公开审计 completion，但不执行 action、不写 memory、不再调用 Provider，终态为 budget_exhausted。已解析且未执行的工具动作以 budget_blocked 记录，不计为工具调用。保留旧文章并显示本次未形成更新。
